# isaacsim-humble-env

Python venv setup for **Isaac Sim 4.5.0** with **ROS2 Humble** integration on Ubuntu 22.04.

---

## Quick Start

```bash
git clone <this-repo> && cd isaacsim-humble-env
chmod +x setup.sh
./setup.sh
# then every session:
source activate_env.sh
```

---

## What Gets Installed

| Component | Version | Notes |
|---|---|---|
| Isaac Sim | 4.5.0 | from `pypi.nvidia.com` |
| Python | 3.10.x | **hard requirement** |
| PyTorch | 2.5.1 | CUDA 12.1 build |
| ROS2 | Humble | via apt, **not pip** |

---

## Prerequisites (before running setup.sh)

### 1. NVIDIA Driver ≥ 525
```bash
nvidia-smi   # check current version
```
Update if needed: https://ubuntu.com/server/docs/nvidia-drivers-installation

### 2. Python 3.10
```bash
python3.10 --version   # should already exist on Ubuntu 22.04
# if not:
sudo apt install python3.10 python3.10-venv python3.10-dev
```

### 3. ROS2 Humble (apt)
```bash
# Follow official instructions:
# https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debians.html
sudo apt install ros-humble-desktop ros-humble-ros-base
```
Isaac Sim's ROS2 bridge talks to your **system** ROS2 install via shared libs.
It does **not** live inside the venv.

## Known Catches & Gotchas

### 🔴 Python version is non-negotiable
Isaac Sim 4.5 requires **exactly Python 3.10**. Using 3.11+ or 3.9 will fail at import.
Isaac Sim 5.x requires Python 3.11 — do not mix them.

### 🔴 NumPy must be < 2.0
`isaacsim` 4.5 breaks with NumPy 2.x. Pinned to `1.26.4` in requirements.txt. Do not
upgrade it without testing.

### 🔴 First launch takes 10–20 minutes
On first run, Isaac Sim downloads Omniverse extension cache from NVIDIA's registry.
This is normal. Do not kill it. Subsequent runs are fast.

### 🔴 EULA prompt on first run
Isaac Sim will ask you to accept the NVIDIA Omniverse License Agreement on first launch.
For headless/CI use, pre-accept it:
```bash
isaacsim isaacsim.exp.full.kit --/app/quitAfter=10 --no-window
# accept in the terminal prompt that appears
```

### 🟡 ROS2 bridge requires `source /opt/ros/humble/setup.bash` BEFORE launching Isaac Sim
The `activate_env.sh` helper does this automatically. If you launch Isaac Sim without
sourcing ROS2, the bridge extension will fail silently or crash.

### 🟡 ROS2 bridge uses system libs, not venv libs
`rclpy`, `sensor_msgs`, etc. come from your apt-installed ROS2. Don't pip install them —
it creates conflicts. The venv just needs to be able to find them at runtime (handled by
sourcing the ROS2 setup.bash).

### 🟡 `FASTRTPS_DEFAULT_PROFILES_FILE` may need setting
If you see DDS/discovery issues between Isaac Sim and ROS2 nodes:
```bash
export FASTRTPS_DEFAULT_PROFILES_FILE=$(pwd)/config/fastdds.xml
```
A working `fastdds.xml` template is in `config/`.

### 🟡 RTX 30/40 series: use CUDA 12.1 PyTorch wheels
The `setup.sh` installs from `https://download.pytorch.org/whl/cu121`. If your system
CUDA is 11.x, this still works because Isaac Sim bundles its own CUDA runtime.

### 🟡 Display / headless rendering
For headless servers (no monitor): Isaac Sim needs a virtual display or `--no-window` flag.
```bash
export DISPLAY=:0   # if using Xvfb
# or pass --no-window to isaacsim for fully headless replicator work
```

### ⚪ Isaac Sim 5.x / Isaac Lab
If you later want Isaac Lab (for RL/training workflows), it can wrap Isaac Sim 4.5.
Isaac Sim 5.x is available but early — stick with 4.5 until the research ecosystem catches up.

## ROS2 Bridge Quick Test

After setup, in one terminal:
```bash
source activate_env.sh
isaacsim isaacsim.exp.full.kit
# Enable: Window > Extensions > search "ROS2 Bridge" > enable
```

In another terminal:
```bash
source /opt/ros/humble/setup.bash
ros2 topic list   # should show /clock and other Isaac Sim topics
```
